# kMoria

Moria for Palm OS, by Bridget Spitznagel (2000–2002). This directory started
as a checkout of the latest CVS revision (tag `Release-2002_03_29`, v0.15) from
the original repository, which is kept with full history in
[`../cvs-repo/kMoria`](../cvs-repo/kMoria).

## Layout

| Path | What it is |
| --- | --- |
| `src/` | The game (C sources, `kMoria.rcp` resources, `Makefile`) |
| `src/kMoriaDB.pdb` | Game-data database (monsters, items, ...) — **must be installed with the app** |
| `src/kMoriaColorDB.pdb` | Optional default colour scheme, generated by `make` from `../tools/make-kmoria-colors.py` |
| `src/BuildDB/` | Palm app that originally generated `kMoriaDB.pdb` |
| `src/ConvertSave/` | Host tool to convert saves to/from UMoria format |
| `src/kMoriaUtil/` | Small companion Palm utility |
| `src/MoriaManual/` | Moria manual as text and as a PalmDOC `.pdb` |

## Building

Requires the [palmdev-macos](https://github.com/savaughn/palmdev-macos)
toolchain (prc-tools / m68k-palmos-gcc 2.95) and the Palm OS SDKs in
`/usr/local/palmdev`.

```sh
# one-time: build a pilrc that can read .bmp files on 64-bit macOS
../tools/build-pilrc.sh        # run from the repo root as ./tools/build-pilrc.sh

cd kMoria/src
make                           # -> kMoria.prc
```

If the toolchain lives somewhere other than
`~/Development/palmdev-macos/toolchain`, pass
`make PALMDEV_TOOLCHAIN=/path/to/toolchain`.

The default target is Palm OS 3.5+ with colour. Other targets (OS 2, OS 3.1
mono) are selectable via the commented `CFLAGS` lines in the Makefile;
`make clean` between them.

### Changes made to build on a modern Mac

- `Makefile`: toolchain paths, `m68k-palmos-multigen` instead of `multigen`,
  `pilot-xfer` install target updated for USB.
- The HandEra SDK headers have CRLF line endings that break gcc 2.95; the
  Makefile makes LF copies in `src/compat/Handera/` at build time.
- Stock pilrc 3.2 misreads every `.bmp` on 64-bit hosts;
  `tools/build-pilrc.sh` builds a patched copy.

### Changes in v0.16

Game changes on top of the original v0.15 source:

- **Here ▸ Stay in place** menu item for the `.` command (wait a turn),
  which previously had no menu entry or tap equivalent. `.` also takes a
  count now (e.g. `20.`), which the original code meant to support but
  never enabled.
- About box, Instructions and the "can't run" screens point to this
  repository instead of the original author's (long-gone) email address
  and SourceForge site. The original copyright and licence text is kept.
- Version bumped to 0.16.
- Optional default colour scheme, `kMoriaColorDB.pdb`, generated by
  `../tools/make-kmoria-colors.py`.

## Testing in CloudpilotEmu

The native `cloudpilot-emu` binary reads CLI commands from stdin. Installing
fails until PalmOS has finished booting, so feed it commands through a file:

```sh
: > /tmp/cmds.txt
tail -f /tmp/cmds.txt | ~/Development/GitHub/cloudpilot-emu/src/cloudpilot/cloudpilot-emu \
    ~/Development/GitHub/cloudpilot-emu/roms/Palm-m515-4.1-en.rom &

# once the emulator window shows PalmOS (from any directory, or a second
# terminal -- the files must be the ones built in kMoria/src):
cd ~/Development/GitHub/palm-roguelike/kMoria/src
echo "install $PWD/kMoria.prc $PWD/kMoriaDB.pdb $PWD/kMoriaColorDB.pdb" >> /tmp/cmds.txt
echo "launch kMoria" >> /tmp/cmds.txt
```

On a freshly booted ROM the first `launch` only dismisses the setup screen;
send it a second time.

### Tungsten C (Palm OS 5)

The ARM emulator `cp-uarm` runs the Tungsten C ROM. Its `install` takes
**one file per command**, and installing only works once the device has
finished its first-boot Setup screens (click through them in the window;
F5 = Home, F6 = Menu). A session saved after setup skips that next time:

```sh
: > /tmp/tc-cmds.txt
tail -f /tmp/tc-cmds.txt | ~/Development/GitHub/cloudpilot-emu/src/uarm/cp-uarm \
    ~/Development/GitHub/cloudpilot-emu/roms/Tungsten-C-setup.session &
# (first time: use roms/Palm-Tungsten-C-nor.bin, finish Setup, then
#  echo "save-session $HOME/Development/GitHub/cloudpilot-emu/roms/Tungsten-C-setup.session" >> /tmp/tc-cmds.txt)

cd ~/Development/GitHub/palm-roguelike/kMoria/src
echo "install $PWD/kMoria.prc"   >> /tmp/tc-cmds.txt
echo "install $PWD/kMoriaDB.pdb" >> /tmp/tc-cmds.txt
echo "install $PWD/kMoriaColorDB.pdb" >> /tmp/tc-cmds.txt
echo "launch kMoria"             >> /tmp/tc-cmds.txt
```

The host keyboard types on the TC's keyboard, so most commands can be typed
directly; `< > ^ {` can't be, so use the Here/Near menus for those.

If commands stop having any effect, the `tail -f` feeding the emulator has
probably exited (e.g. after Ctrl-C). A running emulator can't be reattached
to a new feed, so quit it and start it again with the pipeline above.
