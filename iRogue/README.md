# iRogue

Rogue for Palm OS, by Bridget Spitznagel (2000–2004). This directory is a
checkout of the original CVS repository, which is kept with full history in
[`../cvs-repo/iRogue`](../cvs-repo/iRogue).

## Which version this is

iRogue's CVS trunk stops in April 2001. All later development happened on
the **HandEra branch** (`Release-2001_04_26-Handera-branch`), so this
checkout is the **head of that branch** (16 Jan 2004), not the trunk:

| Point in history | Tag | Notes |
| --- | --- | --- |
| Apr 2001 | `Release-2001_04_26` | trunk head; what a plain `cvs checkout` gives |
| May 2002 | `Release-2002_05_10-on-Handera-branch` | last official release |
| Nov 2003 | — | big reorganisation: `iRogue.c` split into `form_*.c`, old shared-library code merged back in |
| Jan 2004 | `pre-internationalization_20040113` | adds item naming ('c'), on-device colour settings, save-file limit |
| 16 Jan 2004 | *(branch head — this checkout)* | only adds `strings.h` changes, which nothing includes yet |

On top of the branch head come the v1.2 changes described in
[Changes in v1.2](#changes-in-v12).

To check out a different point, use
[`tools/cvs-resolve-tag.py`](../tools/cvs-resolve-tag.py), which works out
what `cvs checkout -r TAG` would produce (branch tags, `Attic/`, deleted
files) from the raw `,v` files:

```sh
cd cvs-repo/iRogue
python3 ../../tools/cvs-resolve-tag.py . Release-2002_05_10-on-Handera-branch |
  while IFS="$(printf '\t')" read rev date file src; do
    mkdir -p "/some/dir/$(dirname "$file")"
    co -q -ko -p"$rev" "$src" > "/some/dir/$file"
  done
```

## Layout

| Path | What it is |
| --- | --- |
| `src/` | The game (C sources, `iRogue.rcp` resources, `Makefile`) |
| `MANUAL.md` | The player's manual |
| `tiles/` | The tile set: `tiles.txt` (the pictures, as text) and `iRogueTileDB-2002.prc` (the original starter set) |
| `build/` | Created by `make`: everything to install (see below) |

## Building

Same toolchain as [kMoria](../kMoria/README.md):

```sh
./tools/build-pilrc.sh     # one-time, from the repo root
cd iRogue/src && make      # -> ../build/
```

`make` puts everything to install in `iRogue/build/`:

| File | What it is |
| --- | --- |
| `iRogue.prc` | The game. On first run it creates `iRogueDB` itself (saved game, high scores). |
| `iRogue-manual.pdb` | Optional Palm DOC e-book of `MANUAL.md`, generated by `../tools/make-irogue-manual.py` |
| `iRogueTileDB.prc` | Optional tile set (Preferences > Tiles), generated from `tiles/tiles.txt` by `../tools/make-irogue-tiles.py` |
| `tiles-preview.png` | Not for the device: every tile, on the white and the black background |

Intermediate files (`.o`, `.bin`, ...) stay in `src/`. `make veryclean`
removes them and `build/`.

The build changes for a modern Mac are the same as kMoria's: toolchain
paths, `m68k-palmos-multigen`, LF copies of the CRLF HandEra SDK headers in
`src/compat/`, and the patched pilrc.

Code space: the main code resource (`.text`) is within about 200 bytes of
the 32 KB limit (`ld: region coderes is full` when it overflows). Put new
functions in `sec_1` or `sec_2`, which have room, by declaring them with
`SEC_1` / `SEC_2` in `prototypes.h`. `m68k-palmos-objdump -h src/iRogue`
shows how full each section is.

## Tiles

Version 1.1.1 (2002) added a **Tiles** preference that draws the map with
10x9 colour pictures from a separate database, `iRogueTileDB`. The release
only came with a starter set (each character drawn as a black letter;
kept here as `tiles/iRogueTileDB-2002.prc`) and asked players to draw
their own, and no finished set seems to have been published.

This version has one: original pixel art for walls, floor, passages, doors,
stairs, traps, every kind of item, the player and all 52 monsters, in the
same colours as the neon text scheme. The pictures live in
[`tiles/tiles.txt`](tiles/tiles.txt) as text, one 10x9 grid per tile, so
they are easy to change; the comments at the top explain the format.
`make` turns it into `build/iRogueTileDB.prc` and
`build/tiles-preview.png`. Characters without a picture (digits and some
punctuation) use the starter set's letter, in grey.

How the game uses the database: the bitmap for map character `c` is the
`(c - 32)`th resource, so there is one for each character from space to
`~`. Food is drawn with the `:` tile, walls with `-` and `|`, and the
dragon's flame with `~`. The tiles are 8-bit with a transparent
background, so they work on both the white and the inverted background.

## Changes in v1.2

Game changes on top of the 2004 branch head (which still called itself
1.1.1, the last release, from May 2002):

- **Neon colours.** A built-in colour scheme: every kind of item and every
  monster has its own vivid colour, chosen to read on both the white and
  the Invert (black) background; walls and `@` stay plain. It is on by
  default for a new install on a colour screen. Previously colour needed a
  hand-written `iRogue-RGB` memo; that memo still works, and now only
  overrides the symbols it lists.
- **5-way navigator** (Tungsten C and other Palm OS 5 devices): up / down /
  left / right walk, holding it keeps walking, and with caps lock on it
  runs. The centre button takes the stairs if you are on them, otherwise
  it searches. The navigator and `hjklyubn` also work in the direction
  picker, and any key or 5-way press closes the map. Before, Up/Down took
  the stairs and left/right did nothing. The plain Up/Down buttons of older
  Palms still take the stairs.
- **Tiles that work.** A complete colour tile set (see [Tiles](#tiles)),
  built with the game. Before, ticking Tiles only gave "Can't find
  tiles" unless you had made your own.
- **Edit Colors** covers every monster (`w`, `I`, `P`, `W`, `X`, `Y` and the
  Amulet were missing), and saving it replaces the `iRogue-RGB` memo
  instead of adding another copy each time.
- About box, License and History updated: no more old email address or
  SourceForge link, the GPL text and credits on one screen, and the story
  since 2002. Instructions rewritten.
- Version bumped to 1.2.
- `MANUAL.md` and an e-book of it, `iRogue-manual.pdb`.

Bug fixes:

- Crash: inventory "call" could stay selected (hidden) and then open the
  naming form on a weapon, which drew a deleted form.
- Memory: an ice monster's freeze lets other monsters move, and a thief
  stealing during it was freed while still being walked over; reading a
  scroll of sleep used (and could free twice) the scroll after it was gone;
  a monster created in a passage read `rooms[-1]`; the "wait, that's a
  ..." message overflowed with 16-letter names; the colour editor wrote one
  past its array; screen clearing in the big font wrote past
  `lines_dirty[]`.
- Saves: loading kept the current game's armour, weapon and rings (phantom
  armour class) and leaked or kept the old level's monsters; the last
  record of every save was left busy; the Restore list crashed when there
  were no saves yet; 30-character player names weren't terminated.
- Leaks: the throw/zap list, the save list and the old pack after "Play
  Again" were never freed.
- Throwing or zapping item 27 or later used the wrong item.
- Dying while asleep stopped you ever falling asleep again in that session.
- Reading identify as your last item left you in an empty, uncancellable
  list.
- Rules, as in Rogue Clone: the three rooms every level needs were always
  the top row; 2-3 rings used more food than 4-8; rings of burden and
  adornment had each other's names; putting on a ring of aggravate monster
  did nothing; monsters chasing you could back away while those heading
  for a door couldn't; create monster never used the squares east or west
  of you.
- Turning on Tiles left the whole Palm in its deepest colour mode after
  you quit; iRogue now puts the screen depth back.
- The wizard-mode warning showed every time; small display over-reads.

Known and left alone: the 1-in-100 "one big room" level is still made as a
normal small room, because enabling it would run code that was never
tested. On Palm OS 5.4+ devices (T5, TX, Treo 650...) the new Memos app
keeps memos elsewhere, so the `iRogue-RGB` memo is ignored there (the
built-in colours still work).

## Testing in CloudpilotEmu

See [kMoria's README](../kMoria/README.md#testing-in-cloudpilotemu) for the
setup. For iRogue only the app (and optionally the manual) is installed:

```sh
cd ~/Development/GitHub/palm-roguelike/iRogue/build
echo "install $PWD/iRogue.prc"        >> /tmp/tc-cmds.txt
echo "install $PWD/iRogue-manual.pdb" >> /tmp/tc-cmds.txt
echo "install $PWD/iRogueTileDB.prc"  >> /tmp/tc-cmds.txt
echo "launch iRogue"                  >> /tmp/tc-cmds.txt
```

In `cp-uarm` (Tungsten C) the Mac's arrow keys are the 5-way and keypad
Enter is its centre button; F6 opens the menu, which the arrows also
navigate.
